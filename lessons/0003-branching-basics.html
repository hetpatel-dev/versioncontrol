Lesson 0003

Branching — Working on Multiple Things at Once

~15 minutes · Mission: Career-ready Git
Goal: Create a branch, work on it, and merge it back. This is the #1 Git skill teams use every single day.

The real-life scenario

Imagine you're on a team. main is the stable, production-ready branch that your teammates and customers rely on. You need to add a new feature — but you can't break main while you experiment. So you create a feature branch, do your work in isolation, then merge it back when it's ready.

This is how every professional team works. Let's do it.

Step 1: See where you are

Check your current branches:

$ git branch

You'll see * main — the asterisk means "this is your current branch." Right now there's only one.

Step 2: Create a feature branch

Let's say we're adding a "Favorite Subjects" column to the student table. We'll work on this in its own branch:

$ git switch -c feature/add-subjects

This creates a new branch called feature/add-subjects and switches to it in one step.

Naming convention Teams use branch naming patterns like feature/..., bugfix/..., hotfix/.... This keeps your branches organized and tells teammates what kind of work is happening.

Now run git branch again — you'll see both branches, with * feature/add-subjects active.

Step 3: Make changes on the feature branch

Edit hands-on/hello.txt to add a "FAVORITE SUBJECT" column to the table:

(Open the file and make it look something like this:)

ROLL NO             NAME OF STUDENT          FAVORITE SUBJECT
    1.              Alice                    Mathematics
    2.              Bob                      Science

Stage and commit:

$ git add hands-on/hello.txt
$ git commit -m "Add favorite subject column to student table"

Step 4: See the branch split

Look at your history now:

$ git log --oneline --graph --all

You'll see the branch diverged from main:

* abc1234 (HEAD -> feature/add-subjects) Add favorite subject column to student table
* 1b3ffc0 (main) Add second entry in students table in hands-on/hello.txt file
* 059d1de Add student table with one entry in hands-on/hello.txt file
...

The history split into two paths. main stayed at the old commit. Your feature branch moved forward. This is the branching superpower — you can experiment without affecting anyone else.

Step 5: Switch back and see main is untouched

$ git switch main

Open hands-on/hello.txt — it's the old version! Your feature changes are safely isolated on the feature/add-subjects branch. This is the point: branches are separate workspaces.

Step 6: Merge your feature back

Now merge the feature into main:

$ git merge feature/add-subjects

This fast-forwards main to catch up with the feature branch (since main hasn't moved since you branched off). Your changes are now in main.

$ git log --oneline --graph --all

The history is a straight line again — but now main has the new feature.

Step 7: Clean up

Delete the feature branch — it's served its purpose:

$ git branch -d feature/add-subjects

git branch -d only deletes if the branch has been merged. Git protects you from losing work.

Optional: Non-fast-forward merge

What if main had moved while you were working? Let's simulate it:

$ git switch -c feature/add-roll-numbers
# (edit: change roll numbers to be 101, 102 instead of 1, 2)
$ git add -A && git commit -m "Change roll numbers to 3-digit format"

$ git switch main
# Make a different change on main
# (edit: add a third student "Charlie")
$ git add -A && git commit -m "Add third student Charlie"

# Now merge — this will NOT fast-forward
$ git merge feature/add-roll-numbers

Git will create a merge commit — a special commit with two parents, joining the two branches.

Career insight On real teams, main almost always moves while you're working on a feature. Real merges create merge commits with two parents. The --graph flag is how you visualize this.

What you just learned

  • git branch — list branches
  • git switch -c <name> — create and switch to a new branch
  • git switch <name> — switch to an existing branch
  • Changes on one branch don't affect others
  • git merge <branch> — bring changes from another branch into the current one
  • git branch -d <name> — delete a merged branch
  • Fast-forward vs merge commits

Practice to build fluency

  1. Create a branch called experiment, make 2 commits, switch back to main — see your files revert
  2. Switch back to experiment, see your files return
  3. Merge it into main and delete it
  4. Try git log --oneline --graph --all after a non-fast-forward merge — see the fork shape
