Branching — Quick Reference

A branch is a lightweight pointer to a commit. Creating branches is nearly instant — you're just creating a new label.

Branch commands

CommandWhat it does
git branchList local branches. * marks current branch.
git branch <name>Create a new branch at current commit
git branch -d <name>Delete a merged branch (safe)
git branch -D <name>Force delete (even if unmerged) ⚠️
git branch -aList all branches (including remote-tracking)
git switch <name>Switch to an existing branch
git switch -c <name>Create + switch to a new branch
git merge <branch>Merge <branch> into current branch

How branches look in history

git log --oneline --graph --all is your main tool. Here's what different situations look like:

Linear (fast-forward merge):
* abc1234 (HEAD -> main) Finish feature
* def5678 Start feature
* 1234abc (origin/main) Previous commit

Merge commit (non-fast-forward):
*   abc1234 (HEAD -> main) Merge feature into main
|\
| * def5678 (feature) Finish feature
* | 1234abc Bugfix on main
|/
* 7890def Base commit

Common branch naming patterns

PatternExample
feature/<name>feature/login-page
bugfix/<name>bugfix/null-pointer
hotfix/<name>hotfix/security-patch
chore/<name>chore/update-deps

Key insight

Branches are just labels. Creating a branch doesn't copy files — it just creates a pointer. That's why branches are cheap and you should use them liberally.
