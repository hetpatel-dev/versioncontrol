Lesson 0004

Connecting to GitHub

~15 minutes · Mission: Career-ready Git
Goal: Push your local repo to GitHub so it's visible online. This is how you showcase your work to employers and collaborate with teams.

The concept: local vs remote

So far, everything has been on your machine (your local repository). GitHub is a remote — a copy of your repo hosted on a server. The magic is that you can sync between them: push your changes up, pull others' changes down.

  Your computer (local)           GitHub (remote)
  ┌──────────────────┐           ┌──────────────────┐
  │  Working Directory│           │  Main branch     │
  │  Staging Area     │  push →  │  Other branches  │
  │  Repository (.git)│           │  Pull Requests   │
  └──────────────────┘  ← pull   └──────────────────┘

Step 1: Create a repo on GitHub

  1. Go to https://github.com and log in as hetpatel-dev
  2. Click the + icon (top-right) → New repository
  3. Repository name: versioncontrol (match your local folder)
  4. Description: "Learning Git & GitHub from scratch"
  5. Keep it Public (employers can see it — that's good!)
  6. DO NOT check "Initialize with README", ".gitignore", or license (your repo already has content)
  7. Click Create repository
Public vs Private Public repos are visible to everyone — great for your portfolio. Private repos are visible only to you and people you invite. Companies use both.

Step 2: Connect your local repo to GitHub

GitHub will show you a page with commands. Look for the section that says "…or push an existing repository from the command line". It'll look like:

$ git remote add origin https://github.com/hetpatel-dev/versioncontrol.git
$ git branch -M main
$ git push -u origin main
What these commands mean
  • git remote add origin <url> — tells Git "there's a remote repo at this URL, call it 'origin'"
  • git branch -M main — renames current branch to main (already done)
  • git push -u origin main — upload commits to GitHub AND set origin/main as the upstream (tracking) branch

Run these commands one by one in your terminal.

Step 3: Handle authentication

The first time you push, Git will ask you to authenticate. You have options:

  • Browser sign-in — Git will open a browser window. Log in to GitHub there.
  • Personal Access Token (PAT) — If browser doesn't work, create a token at GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic). Check "repo" scope, copy the token, paste it as your password.
Note GitHub deprecated password authentication in 2021. You must use a token or browser-based authentication. The Git Credential Manager (installed with Git for Windows) handles this automatically.

Step 4: Verify on GitHub

Refresh your https://github.com/hetpatel-dev/versioncontrol page. You should see:

  • All your files and folders
  • All your commit history
  • The branch main

Step 5: Push your other branches

Your branches only exist locally so far. Push them:

$ git push -u origin experiment

Refresh GitHub — you'll see your experiment branch listed in the branch dropdown.

What you just learned

  • Remote vs local repositories
  • git remote add origin <url> — link to a remote
  • git push -u origin <branch> — push and set upstream
  • Your commits are now visible to employers and collaborators

Practice to build fluency

  1. Make a change, commit, and git push (without -u this time — it's already tracking)
  2. Go to GitHub, see your latest commit appear
  3. Click on a commit on GitHub — see the diff rendered in the browser
