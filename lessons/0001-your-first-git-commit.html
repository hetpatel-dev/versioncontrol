Lesson 0001

Your First Git Commit

~10 minutes · Mission: Career-ready Git
Goal: Make your first Git commit and see it in the history. By the end, you'll understand what version control is and have a concrete record of your work.

What is version control?

A version control system (VCS) tracks changes to your files over time. Think of it like a save point in a video game — you can always go back to an earlier save if something goes wrong. Git is the most popular VCS used by software teams worldwide.

Why does this matter for your career? Every company uses Git. Code review, collaboration, deployment, tracking who wrote what — it all runs through Git. It's not optional; it's the foundation.

Key insight Git stores snapshots of your project, not just differences between files. Each commit is a full picture of every file at that moment.

Step 1: Confirm Git is ready

Open your terminal and run:

$ git --version

You should see something like git version 2.54.0.windows.1. If you see this, Git is installed.

Step 2: Check your identity

Every commit is stamped with your name and email. Git needs to know who you are. Check what's already set:

$ git config --global user.name
$ git config --global user.email

If these show your name and email, you're all set. If not, configure them:

$ git config --global user.name "Your Name"
$ git config --global user.email "your.email@example.com"
Why this matters for your career Companies use this to track who changed what. Your commits will be associated with your GitHub account. Use a real email — ideally the same one you'll use for GitHub.

Step 3: Understand the three states

Git has three places your files can live:

  1. Working Directory — where you edit files (your regular folder)
  2. Staging Area — where you prepare files for a commit
  3. Repository (.git) — where Git permanently stores your snapshots

The flow is: Work → Stage → Commit. You work in your folder, add files to staging, then commit them to the repository.

This is the most important mental model for Git. Everything else builds on it.

Step 4: Make your first commit

This repository (versioncontrol) is already a Git repo. Let's make a change and commit it.

First, check what's happening:

$ git status

You'll see files that are "untracked" — Git sees them but isn't tracking them yet. You'll see your new lessons/, assets/, reference/ folders and markdown files.

Now, let's stage everything and make a commit:

$ git add --all
$ git commit -m "Initialize teaching workspace for Git & GitHub lessons"
Anatomy of a commit git add --all stages all changes. git commit -m "message" creates the snapshot with a message describing what you did and why. Good commit messages are short but descriptive — like a headline.

Step 5: View your history

You just made history. Literally. View it:

$ git log --oneline

You'll see something like:

abc1234 (HEAD -> master) Initialize teaching workspace for Git & GitHub lessons

The jumble of letters and numbers (abc1234) is your commit hash — a unique ID for this snapshot. HEAD means "you are here." master is your branch name.

What you just learned

  • Git is a version control system that takes snapshots
  • The three states: working directory → staging area → repository
  • How to check git status
  • How to stage changes with git add
  • How to commit with git commit
  • How to view history with git log

Practice to build fluency

  1. Create a new file called hello.txt with any content
  2. Run git status — see how Git tells you about it
  3. Stage and commit it
  4. Run git log --oneline again — see two commits now
  5. Modify hello.txt, stage, and commit again

Do this a few times. The goal isn't knowledge — it's fluency. The commands should start feeling automatic.
